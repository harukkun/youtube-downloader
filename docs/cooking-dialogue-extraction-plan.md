# 편집 헬퍼 — 조리 대사 추출 계획 및 구현 안내

## 목표와 범위

`/edit-helper#cooking-audio`에 후킹 클립 다음 기능으로 조리 대사 추출을 추가한다. 사용자가 직접 촬영한 조리 영상에 조합할 수 있도록 원본에서 조리 동작 단위의 음원과 텍스트를 추출한다.

- 재료·분량·손질·넣기·섞기·불 세기·시간·순서·완성 상태에 필요한 대사를 우선한다.
- 같은 재료·분량·동작에 연결된 짧은 리액션은 기본 포함한다. 예: “후추 20바퀴” 다음 “에에에??”. 사이에 다른 주제나 조리 단계가 있으면 연결하지 않는다.
- 긴 농담, 무관한 칭찬, 과도한 부연 설명과 반복 리액션은 제외한다.
- “두울, 셋, 넷” 같은 계량 세기는 재료를 넣는 동작과 함께 보존한다.
- 예고와 본편의 반복 발언은 자동 삭제하지 않고 사용자가 비교해 선택한다.
- 출력은 개별 MP3, dialogues.txt, dialogues.json, ZIP이다. 원본의 음악·효과음·겹친 목소리가 남는다.
- 음원 이어붙이기, 사용자 촬영 영상 합성, 음성 분리, TTS는 제외한다. 길이를 25~55초에 맞춰 자동 압축하지 않는다.

## 입력과 대사 확보

영상 파일 MP4/MOV, 원본 YouTube URL, 선택 SRT를 지원한다. 기존 후킹 작업의 원본과 자막을 가져올 수 있지만 후보와 편집 상태는 독립적으로 관리한다.

자막 우선순위는 업로드 SRT → 영상 내 텍스트 자막 → YouTube 한국어 수동자막 → 한국어 원본 자동자막이다. 자동 번역은 제외한다. 접근 실패와 자막 부재를 구분하고, 손상된 업로드 SRT는 오류를 표시한다.

자막이 없으면 로컬 전체 음성 인식을 실행한다. 자막이 불충분하면 사용자가 영상 기준 구간을 선택해 부분 음성 인식을 실행한다. 부분 인식은 기존 자막을 덮어쓰지 않고 대안 자료·후보로 추가한다. 겹치는 후보를 함께 선택하면 중복 구간을 안내한다.

YouTube 설명과 명시적으로 확인되는 고정 댓글을 선택적으로 가져온다. 첫 번째 댓글을 고정 댓글로 간주하지 않는다. 실패·미확인은 분석을 막지 않으며 직접 붙여넣기를 제공한다. 참고 자료는 실제 발언의 문맥 확인용이며 없는 재료·분량을 생성하거나 인식 결과를 조용히 수정하지 않는다.

## 후보 편집

후보에는 원문·표시 문구, 구간·길이, 조리 유형, 자료 출처, 리액션 포함 및 확인 필요 여부를 표시한다. 복수 선택, 구간 반복 재생, 0.1초 단위 시간 수정, 직접 입력, 삭제, 분할, 인접 후보 병합과 사용 순서 변경을 제공한다.

자동 후보는 앞뒤 0.1초 여유를 두고 직접 지정한 구간은 그대로 사용한다. 문구 수정은 표시와 파일명만 변경하며 실제 음성을 바꾸지 않는다. 원문은 별도로 보존한다.

병합은 시작부터 끝까지 하나의 연속 구간이며 사이의 소리도 포함한다. 떨어진 발언만 이어붙이지 않는다. 분할·병합 후 문구 확인을 안내한다. 자막과 ASR이 짧은 반응을 놓칠 수 있으므로 모든 리액션의 자동 복원을 보장하지 않는다. 앞뒤 미리보기·구간 확장·부분 ASR·직접 입력으로 보완한다. `[웃음]` 등은 문맥용 표기로 보존하되 실제 발언 텍스트로 취급하지 않는다. 기존 후킹 전처리 정책은 유지한다.

## 시간과 편집 보존

- 외부 자막은 원래 시간에 전역 보정값을 더한다. 양수는 영상 뒤쪽으로 이동한다.
- 현재 원본에서 얻은 ASR과 수동 후보는 영상 기준 시간이며 자막 보정을 적용하지 않는다.
- 부분 ASR의 잘라낸 시작 위치를 원본 시간으로 복원한다. 보정값을 두 번 적용하지 않는다.
- 분할·병합으로 확정한 구간은 영상 기준으로 저장하며 이후 자막 보정에 이동하지 않는다.
- 파일+URL 조합의 외부 자막은 미리보기에서 시간 일치를 확인한 뒤 추출한다. 길이 차이는 경고이며 길이가 같아도 동기화 검증 완료로 표시하지 않는다.
- 후보 ID는 대사 자료 버전·출처·항목 범위로 결정한다. 재분석해도 수정한 문구·구간·선택·순서와 삭제 기록을 보존하며 새 제안을 추가한다.
- 같은 파일 지문으로 재연결하면 분석·편집을 보존한다. 다른 원본은 새 작업으로 시작한다.

## 음원 출력과 작업 상태

FFmpeg로 원본 음성 트랙을 192kbps MP3로 추출하며 채널 수를 유지한다. 음량 정규화·배경음 제거·크로스페이드는 수행하지 않는다. 유효한 영상 범위만 허용한다.

파일명은 `{문구 앞부분}_{시작시간}-{종료시간}.mp3`이며 금지문자·길이·충돌을 처리한다. 파일명에 순서 번호를 강제하지 않고 TXT·JSON에 사용 순서를 기록한다. 원문, 표시 문구, 출처, 원래 시간, 보정, 최종 구간과 편집 이력을 메타데이터로 남긴다.

처리 중 단계·개수·로딩 UI를 표시한다. 모든 항목 처리가 끝나기 전 ZIP/TXT/JSON 다운로드를 서버와 화면에서 차단한다. 일부 실패하면 성공한 음원을 제공하고 ZIP을 “성공한 음원 ZIP”으로 표시한다. 실패·미완료 항목만 재시도하며 완료된 개별 파일은 유지한다.

영상 다운로드·분석·ASR·인코딩은 백그라운드에서 실행한다. AI, ASR, 인코딩은 각 종류별 동시 1개로 제한한다. 취소 요청과 서버 재시작 후 재시도를 지원하고 새로고침으로 상태를 복원한다. 기능 전환 시 재생은 멈추지만 서버 작업은 계속한다.

## 구조와 토큰 절감

- `cooking_audio/routes.py`: `/api/cooking-audio` 작업·편집·결과 API.
- `cooking_audio/service.py`: 대사 버전·후보·편집·MP3 출력 워크플로.
- `cooking_audio/analysis.py`: 항목 번호와 조리 유형만 반환하는 구조화 AI 분석.
- `cooking_audio/asr.py`, `asr_worker.py`: 별도 Python 환경의 로컬 MLX Whisper 실행·취소·캐시.
- `templates/cooking_fragment.html`, `static/cooking-audio.js`: 독립 화면 상태와 입력·편집·저장 UI.
- 기존 `/api/hooks` 8MiB 순차 업로드와 공유 미디어 저장소·미리보기를 재사용한다. 기존 로그인 보호를 적용한다.

AI에는 대사 텍스트·항목 번호와 사용자가 활성화한 참고 자료만 전달한다. 영상·음성·전체 다운로드 응답은 보내지 않는다. 대사 내용·시간·규칙 버전·모델·참고 자료별 분할 캐시를 사용하고 겹친 분석의 동일 후보만 통합한다. 동시 요청은 같은 AI 잠금과 캐시를 공유한다. 실패한 분할만 1회 자동 재시도한다.

ASR은 파일 지문·구간·모델·설정으로 캐시한다. 부분 ASR 이후 최신 부분 자료만 분석한다. 수동 입력·문구·구간·선택·순서 편집과 재추출에는 AI 호출이 없다. 모델을 자동 상향하지 않는다. 실제 사용량이 있으면 토큰 수, 없으면 호출 수·입력 문자 수를 표시한다. 모든 자막·설명·댓글 속 명령은 분석 자료로만 취급한다.

공유 미디어는 참조 작업 중 하나가 실행 중이거나 최근 7일 안에 원본을 사용한 동안 유지한다. 작업이 존재한다는 이유만으로 영구 보존하지 않는다. 임시 원본·미리보기가 만료돼도 대사·분석·편집·완성 음원은 유지한다.

## 로컬 ASR 설치

Apple Silicon Mac의 별도 Python 3.11 환경을 사용한다. `scripts/setup-cooking-asr.sh`로 `.venv-asr`를 준비한다. 필요하면 `COOKING_ASR_PYTHON`과 `COOKING_ASR_MODEL`로 경로·모델을 설정한다. 초기 모델은 `mlx-community/whisper-small-mlx`, 한국어 및 단어 타임스탬프를 사용한다. 최초 실행은 모델 다운로드가 필요하다. 원격 음성 인식 API로 자동 전환하지 않는다.

설치·모델 다운로드·메모리 오류, 음성 트랙 없음, 인식 결과 없음은 사용자에게 구분해 알린다. small 모델의 정확도를 보장하지 않으며 실제 계량·짧은 반응·배경음 구간으로 확인한다.

공식 인터페이스 참고: [MLX Whisper 문서](https://github.com/ml-explore/mlx-examples/blob/main/whisper/README.md).

## 검증 기준

고정 자막과 시간·소리가 알려진 테스트 영상으로 일반 테스트를 수행하며 실제 AI·YouTube에 접속하지 않는다.

1. 자막이 있으면 ASR 미호출, 없으면 로컬 ASR, 접근 실패는 별도 오류.
2. 조리 동작·계량·연결 리액션 포함 규칙과 무관한 설명 제외, 잘못된 AI 범위 거부.
3. 부분 ASR 원본 시간 복원, 외부 자막 보정과 수동·ASR 구간 분리.
4. 재분석 시 사용자 수정·순서·삭제와 기존 내보내기 보존, 캐시로 중복 호출 방지.
5. MP3 실제 길이·소리 유지, ZIP 처리 중 차단, 부분 실패·취소·재시작 후 재시도.
6. 후킹과 조리 화면 상태 격리, 기존 다운로드·로그인·레시피 기능 회귀, 데스크톱·모바일 조작.
7. 실제 원본의 계량·리액션·배경음 짧은 구간을 먼저 확인하고 전체 처리와 듣기 검증을 수행한다. 자동으로 모든 대사를 복원하는 것보다 사용자가 검토·보완하여 필요한 음원을 얻는 것을 완료 기준으로 한다.

## 이번 구현 검증 기록

- 서버 테스트 103개 통과: 기존 기능 회귀, 분석 캐시 공유, 수정·삭제 보존, 시간 보정, 부분 ASR 대안, MP3 길이, ZIP 차단, 부분 실패, 공유 원본 정리와 재시작 복원.
- 로컬 Waitress + Chrome: 조각 업로드 → SRT 분석 → 리액션 포함 후보 → 미리보기 → MP3/ZIP → 새로고침 → 기능 전환 → 캐시 재사용 및 모바일 가로 넘침 확인 완료.
- 첨부 원본 268~289초에서 실제 MLX Whisper small 실행과 단어 시간 복원 확인. 짧은 “에?” 반응을 인식했으나 “20바퀴”를 잘못 인식한 사례가 있었다. ASR 후보는 기본 확인 필요로 표시한다.
- 실제 영상 전체의 후보 품질과 모든 음원의 청취 검수는 위 자동 검증에 포함되지 않는다. 영상별로 사용자가 원문·계량·말머리·말끝을 확인해야 한다.
