# 업로드 프로세스 — 사용자 설정 TODO

로컬 앱 코드와 테스트는 준비되어 있습니다. 아래 Google Sheets / Apps Script 작업은 사용자가 직접 진행합니다. 실제 유튜브에 영상을 게시하는 기능은 아닙니다.

## 1. 기존 코드와 시트 백업

1. 현황판 스프레드시트를 엽니다.
2. **파일 → 사본 만들기**로 시트의 백업을 만듭니다.
3. 원래 시트에서 **확장 프로그램 → Apps Script**를 엽니다.
4. 현재 `Code.gs` 전체를 별도 텍스트 파일에 복사해 둡니다.

## 2. 새 Apps Script 코드로 교체

1. 이 프로젝트의 `sheets/Code.gs` 전체를 복사합니다.
2. 원래 시트에 연결된 Apps Script 편집기의 기존 `Code.gs` 내용을 교체합니다. 맨 아래에 중복해서 붙이지 마세요.
3. 저장합니다. 코드의 `UPLOAD_VERSION` 값이 `12`인지 확인합니다.
4. **현황판 Y열(숨김)의 항목 ID가 이미 존재하면 `setupSheets`를 다시 실행할 필요가 없습니다.**
5. Y열/항목 ID가 없는 구버전 시트만 백업을 확인한 다음 `setupSheets`를 실행합니다. ID 중복이 있는 행은 기존 ID를 임의로 복제하지 말고 원본/복제 행을 확인합니다.

## 3. 고급 Google Sheets 서비스 활성화

1. Apps Script 편집기 왼쪽 **서비스 옆 +**를 누릅니다.
2. **Google Sheets API**를 선택합니다.
3. 버전 **v4**, 식별자 **Sheets**로 추가합니다. 이미 있다면 중복 추가하지 않습니다.
4. 별도의 표준 Google Cloud 프로젝트를 연결한 경우, 해당 Cloud 프로젝트의 **API 및 서비스 → 라이브러리 → Google Sheets API → 사용**도 확인합니다. 기본 Apps Script Cloud 프로젝트는 서비스 추가 시 자동 활성화됩니다.

공식 안내: [고급 Google 서비스 활성화](https://developers.google.com/apps-script/guides/services/advanced)

## 4. 권한과 웹 앱 배포

1. **배포 → 배포 관리**를 엽니다.
2. 기존 웹 앱 배포를 선택하고 **수정(연필) → 버전: 새 버전 → 배포**를 누릅니다.
3. 실행 계정은 **나**, 액세스 권한은 기존 앱 연결과 동일한 **모든 사용자**로 유지합니다. 앱은 별도의 업로드 토큰으로 쓰기 요청을 인증합니다.
4. 새 권한 승인이 표시되면 코드와 요청 권한을 확인한 뒤 승인합니다.
5. 기존 배포를 업데이트하면 웹 앱 URL과 저장된 토큰을 계속 사용할 수 있습니다. 별도 새 배포를 만든 경우에만 새 `/exec` URL을 앱에 반영합니다.
6. 웹 앱 `/exec` 주소를 브라우저로 열어 응답의 `version`이 `12`인지 확인합니다.

## 5. 로컬 앱 재시작과 연결 확인

1. 실행 중인 로컬 앱을 종료한 뒤 평소 방법으로 다시 시작합니다.
2. **쇼츠 현황판 → 시트 쓰기 연결**에서 기존 URL·토큰이 유지되는지 확인합니다. 새 배포 URL을 만들었다면 업데이트합니다.
3. 브라우저를 새로고침하고 상단 **업로드 프로세스**를 엽니다.
4. 완료되지 않은 항목을 선택해 기본 정보가 표시되는지 확인합니다.
5. `Google Sheets 서비스` 또는 `버전` 안내가 나오면 2–4단계를 확인합니다. 목록은 보이지만 선택이 실패한다면 시트 읽기 연결뿐 아니라 쓰기 연결·고급 서비스·항목 ID를 확인합니다.

## 6. 테스트 항목으로 전체 흐름 확인

1. 현황판에 작업용 테스트 항목 하나를 준비하고 업로드 완료 이전 상태로 둡니다.
2. **업로드 프로세스**에서 테스트 항목을 선택합니다.
3. 영상 제목·원본 링크·참고 링크를 입력합니다. 설명 입력은 다음 단계에서 합니다.
4. 원본 레시피를 붙여 넣고 SNS 글을 생성합니다. 추가 질문이 나오면 답변합니다.
5. **유튜브** 결과를 수정하고 **유튜브 설명글 확정**을 누릅니다.
6. 썸네일을 만들고 **현재 썸네일 확정**을 누르거나 **기존 썸네일 사용**을 선택합니다.
7. 새로고침하여 초안과 확정한 이미지가 복원되는지 확인합니다. 원본 영상과 미확정 편집 장면은 보관하지 않습니다.
8. 최종 확인에서 먼저 제출 얼럿을 **취소**합니다. 시트가 바뀌지 않아야 합니다.
9. 다시 제출하고 **승인**합니다. 제목·설명·링크·메모·썸네일과 `✅ 업로드 완료` 상태가 반영되는지 확인합니다.
10. 최종 확인의 **유튜브 링크 (선택)**에 링크를 입력했다면 유튜브 체크와 유튜브 링크가 함께 저장되는지 확인합니다. 비워두면 기존 플랫폼 체크·게시 링크가 유지되어야 합니다. 다른 플랫폼·고정 댓글·등록일도 유지되는지 확인합니다.

## 저장·복원 안내

- 초안은 같은 브라우저/사이트 주소에서만 복원됩니다. 다른 PC나 브라우저로 동기화되지 않습니다.
- 최종 확인에서 입력한 유튜브 링크도 초안에 저장됩니다. 이 기능을 사용하려면 수정된 `sheets/Code.gs`로 기존 Apps Script 웹 앱을 새 버전으로 배포해야 합니다.
- 썸네일 단계의 **이미지 저장**은 다운로드만 합니다. 시트 반영은 마지막 승인 때 이루어집니다.
- 저장 응답이 끊기면 **저장 결과 확인**을 먼저 누릅니다. 완료 기록이 없을 때만 같은 번호로 재제출합니다.
- 다른 사람이 수정했거나 항목이 삭제되면 초안을 유지하고 제출을 중단합니다. 필요한 내용을 복사한 뒤 **최신 내용으로 다시 시작**을 선택합니다.
- 새 이미지 준비와 시트 저장은 별개입니다. 확실한 실패는 새 파일을 정리하고, 불확실한 결과는 확인 전까지 보관합니다.
- 시트 셀과 제출 기록은 한 번의 Sheets API 요청으로 저장됩니다. Apps Script 잠금은 시트에서 직접 수행하는 동시 편집까지 막지는 않습니다.
- 생성 기능에는 기존 헬퍼에서 사용하던 Codex/Claude 호출 환경이 필요합니다.

## v16: 어필리에이트 링크 열 · 열 순서 · 촬영 완료 이모지

현황판에 `🛒 어필리에이트 링크` 열을 추가하고, `✍️ 내 영상 정보` 그룹을 `🚀 업로드 플랫폼` 앞으로 옮기며, 촬영 완료 상태를 `🎞️ 촬영 완료`로 바꿉니다.
업로드 프로세스의 SNS 설명글 단계에서 입력한 쿠팡 링크는 최종 제출 때 이 열에 `제품명: 링크` 줄로 저장됩니다.
새 항목을 열면 시트에 저장된 어필리에이트 링크가 쿠팡 링크 입력란에 미리 채워집니다.

아래 1–3단계는 **중간에 다른 편집 없이 이어서** 진행합니다. 코드만 바뀌고 시트 열이 옮겨지기 전에는 편집 트리거가 잘못된 열에 날짜를 쓰거나 값을 되돌릴 수 있습니다.

1. 시트를 백업(파일 › 사본 만들기 또는 버전 기록 확인)한 뒤 Apps Script 편집기에서 `Code.gs` 전체를 최신 `sheets/Code.gs`로 교체하고 저장합니다. `UPLOAD_VERSION`이 `16`인지 확인합니다.
2. 시트 메뉴 **쇼츠 현황판 › 🎨 시트 초기 설정**(`setupSheets`)을 실행합니다. 기존 데이터는 열과 함께 이동하고, `🎥 촬영 완료` 셀은 `🎞️ 촬영 완료`로 바뀝니다. 항목 ID는 유지됩니다.
3. **배포 관리 → 수정(연필) → 버전: 새 버전 → 배포**를 진행합니다. `/exec` 응답의 `version`이 `16`인지 확인합니다.
4. 로컬 앱을 재시작합니다. 시트 열 순서가 바뀌어도 웹 현황판은 헤더 이름으로 읽으므로 추가 설정은 필요 없습니다.

- 시트를 옮기기 전(`setupSheets` 미실행)에는 업로드·현황판 편집이 `upgrade_required`로 거절됩니다. 새 버전을 배포하기 전에는 어필리에이트 링크를 보내는 최종 제출이 `bad_fields`로 거절됩니다.
- `레퍼 쇼츠` 탭에 남은 `🎥 촬영 완료` 표시는 해당 영상이 다음에 동기화될 때 새 라벨로 바뀝니다.
- `🎥 촬영 완료` 항목을 업로드 프로세스에서 작업 중이었다면, 라벨이 바뀌면서 "시트 내용이 변경되었습니다" 안내가 뜰 수 있습니다. 초안을 확인한 뒤 최신 내용으로 다시 시작합니다.

## v17: 요리사전 비공개 초안 연동

1. 시트를 백업한 뒤 최신 `sheets/Code.gs`로 교체하고 **시트 초기 설정**을 실행합니다. 마지막에 요리사전 기본정보·재료·만드는 순서·사진 URL·데이터 버전·수정일 컬럼이 추가됩니다. 기존 열과 항목 ID는 유지됩니다.
2. Apps Script 웹 앱을 새 버전으로 재배포하고 로컬 유틸을 재시작합니다.
3. 업로드 프로세스에서 썸네일을 확정하면 글씨 없는 요리 사진도 함께 준비됩니다. 기존 썸네일을 사용하면 최종 확인에서 요리 사진을 선택하세요.
4. 최종 확인의 **레시피 정보 준비**를 누르고 추출 내용을 확인한 뒤 현황판에 제출합니다. 준비에 실패하면 다시 시도하거나 `요리사전 비공개 초안도 준비하기`를 끄고 기존 방식으로 제출할 수 있습니다. 끄고 제출한 항목은 자동 가져오기 대상이 아닙니다.
5. 시트 메뉴 **요리사전 읽기 연결 정보**로 읽기 전용 토큰을 확인하고 cook-dict 서버의 `COOK_DICT_READ_TOKEN`, `COOK_DICT_SHEET_ID`, `COOK_DICT_SHEETS_URL`을 설정합니다. 쓰기 토큰은 요리사전에 전달하지 않습니다.
6. cook-dict에 새 DB 마이그레이션과 코드를 배포한 뒤 관리자 **현황판 가져오기 → 지금 가져오기**로 확인합니다. 모든 항목은 비공개 초안이며 새 재료/인물 확인 후 비공개 레시피로 등록합니다. 공개는 별도로 선택합니다.
7. 자동 가져오기는 **6시간 간격, 하루 4회**입니다. Apps Script의 스크립트 속성에 `COOK_DICT_SITE_URL`(요리사전 HTTPS 주소), `COOK_DICT_CRON_SECRET`(cook-dict의 `CRON_SECRET`과 동일, 16자 이상)을 설정하고 메뉴 **요리사전 6시간 자동 가져오기 설치**를 실행합니다. 기존 같은 핸들러의 타이머만 교체합니다. 그 사이 변경은 관리자의 **지금 가져오기**로 확인합니다. Vercel의 별도 보조 스케줄은 사용하지 않습니다.

사진 두 장은 Drive에서 공개 링크로 읽을 수 있게 저장됩니다. 사진 준비 실패 시 시트 행은 바뀌지 않습니다. 저장 결과가 불확실하면 사진을 보관하고 기존 **저장 결과 확인 → 같은 번호로 재시도** 흐름을 사용합니다. 기존 업로드 완료 항목에는 새 컬럼과 원본 사진이 없으므로 소급 자동 등록하지 않습니다.

검증: `.venv/bin/python -m unittest tests.test_cook_dict tests.test_upload_process -q`, `node tests/test_cook_dict_script.js`. 운영 계정이나 시트에 쓰지 않습니다.

## 기존 업로드 완료 레시피 일괄 준비 (v18)

1. `sheets/Code.gs` v18을 저장하고 기존 웹 앱을 **새 버전으로 재배포**합니다. 요리사전 컬럼이 없으면 시트의 **쇼츠 현황판 → 시트 초기 설정**도 실행합니다. 유틸 서버를 재시작합니다.
2. `/shorts`의 **기존 완료 항목 레시피 준비**를 눌러 대상 목록과 건수를 확인합니다. 이때는 읽기만 합니다. 업로드 완료이면서 요리사전 컬럼 6개가 모두 빈 행만 대상입니다.
   - Google 응답 주소 이동 문제를 줄이기 위해 조회에는 시스템 `curl`이 있으면 사용합니다. 각 요청은 25초 제한으로 최대 3회 시도하며, 저장 요청은 자동 반복하지 않습니다.
   - 조회 중 확인된 대상 수가 표시됩니다. 중간에 실패하면 페이지를 새로고침하지 말고 **대상 다시 확인**을 누르세요. 같은 화면에서 중단된 페이지부터 이어서 조회합니다. 전체 조회가 끝나야 처리 시작이 활성화됩니다.
3. **처리 시작**을 누르면 현재 AI 설정으로 기존 게시 설명글을 한 건씩 추출·저장합니다. 재료·조리법이 없으면 내용을 만들어내지 않고 실패로 남깁니다. 원본 설명글, 상태, 플랫폼 링크, 기존 썸네일은 그대로 유지합니다.
4. **실패한 항목 재시도**, **현재 항목 후 중지**를 지원합니다. 저장 응답을 놓친 경우에도 재시도 시 기존 컬럼을 확인해 중복 처리를 막습니다. 설명글을 수정했다면 **대상 다시 확인**을 누르세요. 브라우저를 닫으면 다음 항목은 실행하지 않으며, 저장한 행은 유지됩니다.
5. cook-dict도 최신 코드로 실행/배포한 뒤 **지금 가져오기**를 누릅니다. 사진이 없는 기존 항목도 비공개 초안으로 들어오며, 사진을 추가한 뒤 레시피로 등록합니다. 완성 썸네일을 글씨 없는 사진으로 대신 사용하지 않습니다.

이 기능은 유틸의 기존 쓰기 연결을 사용합니다. 요리사전 읽기 토큰으로는 보완 작업을 수행할 수 없습니다. 자동 가져오기는 기존처럼 6시간 간격이며, AI 일괄 처리는 버튼으로 시작할 때만 실행합니다.

검증: `.venv/bin/python -m unittest tests.test_cook_backfill -q`, `node tests/test_cook_backfill.js`, `node tests/test_cook_backfill_script.js`.
