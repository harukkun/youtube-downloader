# 아티클 빌더

업로드 헬퍼의 **아티클 빌더**(`/helper#article`)에서 업로드 완료한 요리의 설명을
블로그·커뮤니티용 글로 정리하고 조리 단계마다 영상 스틸컷을 붙입니다.

## 준비

1. 서버를 새 코드로 다시 시작합니다.
2. 현황판의 Apps Script를 `sheets/Code.gs`로 업데이트하고 **배포 관리 → 수정 → 새 버전**으로 배포합니다.
   이 기능은 **버전 15, article_version 1**을 사용합니다. 기존 시트 열을 변경하거나 초기화할 필요는 없습니다.
3. 누락값을 현황판에 저장하려면 기존 Apps Script URL·토큰 연결과 고급 Google Sheets 서비스가 필요합니다.
   쓰기 연결이 없더라도 필수 정보가 완성된 항목은 CSV 읽기로 시작할 수 있습니다.
4. FFmpeg·ffprobe와 기존 LLM 호출 환경을 사용합니다. 자막 없는 영상의 음성 인식은 선택 사항이며,
   `scripts/setup-cooking-asr.sh`로 설치하거나 `COOKING_ASR_PYTHON`을 설정합니다. 없으면 수동 구간 지정을 사용합니다.

## 작업 순서

1. **요리 선택**: 업로드 완료 항목을 선택합니다. 내 영상 제목·설명(레시피)·업로드 플랫폼의 유튜브 링크가 필수입니다.
   참고 원본 링크가 아닌 **게시한 유튜브 링크**를 다운로드합니다. 빈 필드만 입력하며 현황판에도 저장됩니다.
2. **글 작성**: 템플릿과 생성 지시를 확인하고 ‘아티클 생성’을 누릅니다. 추가 질문이 있으면 답변합니다.
   새 후보를 적용한 뒤 제목·소개·재료·조리 단계·마무리를 직접 편집합니다. 단계 추가·삭제·순서 변경이 가능합니다.
3. **영상 준비**: 다운로드·재생 준비 후 자막/음성 인식을 준비합니다. ‘구간 자동 제안’은 각 조리 단계에 해당하는
   자막 구간을 제안합니다. 직접 구간을 지정하려면 자막 준비와 자동 제안을 생략해도 됩니다.
4. **장면 선택**: 단계별 시작·끝 시간을 정하고, 후보 장면 또는 ±0.1초 탐색으로 시점을 선택합니다.
   위·아래 제외 영역을 지정하고 정사각형을 드래그하거나 위치·확대를 조절한 후 이미지를 추출·확정합니다.
5. **내보내기**: 초안 본문은 언제든 복사할 수 있습니다. 모든 단계의 본문·구간·이미지가 확정되면 완성본 ZIP을 받습니다.
   `article.md`, `article.html`, `images/step-01.jpg` 등이 포함됩니다. 이미지가 붙여넣어지는지는 게시 플랫폼에 따라 다르므로 파일을 직접 첨부합니다.

자막과 실제 화면은 다를 수 있습니다. 자동 제안은 텍스트 기반 후보이며, 화면을 AI로 분석하거나 정답을 확정하지 않습니다.
여러 단계가 같은 구간을 사용할 수 있고, 영상 순서가 레시피 순서와 달라도 됩니다. 후보 스틸컷 5장은 균등한 시점에서 추출됩니다.
다운로드가 실패하면 동일한 업로드본 MP4/MOV를 선택할 수 있습니다. 이때 원격 자막은 재사용하지 않습니다.

## 템플릿과 생성 설정

기본 파일은 `article_builder/templates/article-template.md`입니다. 화면의 textarea에서 수정합니다.

- 슬롯: `{{title}}`, `{{intro}}`, `{{ingredients}}`, `{{steps}}`, `{{closing}}`, `{{youtube_url}}`.
- `{{steps}}`와 `{{youtube_url}}`은 각각 한 번 포함해야 합니다. 단계 번호와 이미지는 앱이 삽입합니다.
- 제목(`#`), 문단, 줄바꿈, 목록(`-`), 굵은 글씨, 코드, HTTPS 링크를 지원하는 제한된 Markdown입니다.
  HTML 태그와 임의 이미지 삽입은 실행하지 않습니다.
- ‘현재 초안에 적용’은 해당 초안의 구성을 변경합니다. 기본 설정 저장은 다음 아티클에만 적용됩니다.
- 재생성은 새 후보를 만들며, 적용 전까지 기존 편집 내용을 유지합니다. 적용하면 새 단계의 이미지 연결을 다시 지정해야 합니다.

## LLM 사용과 비용 표시

| 작업 | LLM 사용 |
|---|---|
| 아티클 생성·추가 답변 반영·새 결과로 다시 생성 | 사용 |
| 자막과 단계의 구간 자동 제안·다시 분석 | 사용 |
| 현황판 조회·보완 저장·직접 편집·템플릿 변경 | 없음 |
| 다운로드·자막 조회·로컬 Whisper·이미지 추출·크롭·ZIP | 없음 |

동일 입력의 성공 결과는 캐시를 재사용합니다. ‘새 결과로 다시 생성’과 ‘다시 분석’은 캐시를 우회합니다.
실패한 호출은 자동 재시도하지 않습니다. 긴 자막은 나눠 분석하므로 버튼 한 번에 여러 호출이 발생할 수 있습니다.
API 방식은 제공된 입력/출력 토큰을 표시하고, CLI 방식은 호출 횟수·처리 시간·제공된 비용만 표시합니다.
제공되지 않은 토큰은 ‘확인 불가’로 표시합니다. 영상·이미지는 LLM으로 전송하지 않습니다.

## 저장과 충돌 처리

- 설정: `~/.youtube-downloader/helper.json`의 `article` 항목.
- 초안·이미지·결과: `~/.youtube-downloader/articles/`; `ARTICLES_DATA_DIR`로 변경 가능.
- 직접 편집은 자동 저장합니다. 다른 탭에서 수정했다면 입력을 보존하고 버전 충돌을 표시합니다.
  현재 입력을 복사한 뒤 최신 초안을 다시 여세요. 오래된 백그라운드 결과는 최신 편집을 덮어쓰지 않습니다.
- 현황판 저장은 항목 ID를 따라 이동한 행을 찾고 제목·설명·게시 URL·상태를 비교합니다.
  같은 요청 ID의 재시도는 중복 저장하지 않습니다. Apps Script 잠금은 시트에서의 직접 편집까지 잠그지는 않습니다.
- 단계 재정렬은 이미지 연결을 유지합니다. 단계 내용 수정·시점/크롭 변경·영상 교체는 필요한 이미지 확정을 해제합니다.
- 원본·미리보기 영상은 7일 미사용 후 정리합니다. 확정 이미지가 있으면 원본 없이도 내보낼 수 있습니다.
  장면을 바꾸려면 영상을 다시 준비해야 하며, 만료된 로컬 영상은 다시 선택해야 합니다.
- 초안·확정 이미지·완료 ZIP은 자동 삭제하지 않습니다. 초안 삭제 시 작업 폴더 전체를 제거합니다.

## 검증

유료 LLM·Google·YouTube 호출 없이 모킹한 통합 테스트와 실제 FFmpeg 샘플 영상을 사용합니다.

```bash
.venv/bin/python -m unittest tests.test_articles
node tests/test_article_script.js
```

브라우저 검증은 Playwright와 Chrome이 필요합니다. 설치된 런타임의 `node_modules`를 `NODE_PATH`로 지정할 수 있습니다.

```bash
.venv/bin/python tests/run_article_browser.py
```

테스트 실행기는 임시 서버와 데이터 폴더를 만들고 종료 시 정리합니다. 아티클 생성·캐시·저장/복원·자막 연결·스틸컷·크롭·ZIP·다중 탭 충돌·모바일·기존 helper 탭을 검증합니다.
