# 자동 편집

`/auto-edit`에서 여러 영상 또는 기존 CapCut 프로젝트를 받아 무음·정지 구간을 제거합니다.
FFmpeg로 분석하고 [pyCapCut](https://github.com/GuanYixuan/pyCapCut) 0.0.3으로 편집 가능한 초안을 생성합니다.
AI 서비스에 영상을 전송하지 않습니다.

## 입력과 편집 기준

- 영상: MP4/MOV, 파일당 2 GB, 최대 40개. 목록의 화살표로 재생 순서를 바꿀 수 있습니다.
- 프로젝트: 이 컴퓨터의 프로젝트 목록에서 선택하거나 `draft_info.json` / `draft_content.json`을 첨부합니다.
- 프로젝트의 원본 경로가 없으면 동일한 파일 이름의 영상을 함께 첨부합니다. 이름이 중복되면 오류를 표시합니다.
- 무음: 기본 -35 dB, 0.7초 이상. 오디오 트랙 자체가 없는 영상은 무음으로 처리하지 않습니다.
- 정지: 320px로 축소한 프레임을 FFmpeg `freezedetect`로 비교합니다. 기본 -50 dB, 1.5초 이상.
- 기본값은 **무음 또는 정지**입니다. 정지 화면의 대사를 유지하려면 **무음이면서 정지**를 선택하세요.
- 기본적으로 제거 구간 앞뒤 0.12초를 남깁니다.

프로젝트 입력은 영상·오디오 트랙의 원본 시간 범위를 타임라인 시간으로 변환하고, 각 트랙에서
소리가 나거나 움직이는 구간을 합쳐 분석합니다. 분석은 원본 미디어 기준이므로 캡컷의 오디오 효과나
합성 후 최종 영상의 분석과 다를 수 있습니다. 제거할 시간이 정해지면 자막·음악·오버레이도 같은
구간을 제거하고 앞으로 이동합니다. 일정한 배속과 기존 배치·볼륨·정적인 스타일은 유지합니다.

암호화된 프로젝트, 복합 클립, 전환, 곡선 변속, 역재생, 반복, 키프레임, 애니메이션, 페이드는
시간 보정을 보장할 수 없어 오류로 안내합니다. 해당 프로젝트는 CapCut에서 영상으로 내보내 입력하세요.

## 저장과 복원

- 작업 정보와 결과는 기본 `~/.youtube-downloader/auto-edit/jobs/<id>/`에 저장됩니다.
- 사용하는 원본 미디어를 작업 폴더에 복사하여 업로드 임시 파일이 만료되어도 편집본이 유지됩니다.
- 원본 프로젝트는 덮어쓰지 않습니다. JSON 다운로드에는 이 컴퓨터의 절대 소스 경로가 포함됩니다.
- 새로고침 후 마지막 작업을 복원하며 최근 편집 목록에서 결과를 다시 선택할 수 있습니다.
- 서버 재시작으로 중단된 작업은 중단 상태로 표시합니다. 입력을 다시 선택해 새 작업을 시작하세요.
- 결과와 원본 복사본은 자동 삭제하지 않으므로 긴 영상 작업 시 저장 공간을 확보하세요.

`AUTO_EDIT_DATA_DIR`로 작업 위치, `CAPCUT_DRAFTS_DIR`로 캡컷 프로젝트 폴더를 바꿀 수 있습니다.
외부 접속 시에도 캡컷 열기는 브라우저 접속자가 아니라 **서버 컴퓨터**에서 수행됩니다.

## 검증

```sh
.venv/bin/python -m unittest tests.test_auto_edit -v
```

실제 FFmpeg 합성 영상으로 무음·정지 탐지, 여러 소스 결합, 소스 보관, pyCapCut 재입력,
자막/오디오 동기화, 고정 배속, 경계 구간, API 오류 및 교차 출처 요청 거부를 확인합니다.

브라우저 테스트는 `/tmp/autocut-fixture.mp4`에 6초 영상(2~4초 무음)을 준비한 뒤 실행합니다.

```sh
ffmpeg -v error -f lavfi -i testsrc2=size=320x180:rate=30:duration=6 \
  -f lavfi -i sine=frequency=440:duration=6 \
  -af 'volume=enable=between(t\,2\,4):volume=0' \
  -c:v libx264 -c:a aac -y /tmp/autocut-fixture.mp4
AUTO_EDIT_DATA_DIR=/tmp/autocut-ui-data HOOKS_DATA_DIR=/tmp/autocut-ui-hooks PORT=8879 \
  .venv/bin/python app.py --no-browser
# 별도 터미널, Playwright와 Chrome 필요
node tests/test_auto_edit_browser.js
```

브라우저 테스트는 실제 업로드·분석·프로젝트 재입력·새로고침 복원·모바일 레이아웃을 검증합니다.
캡컷 실행 API만 가로채므로 네이티브 앱 열림 검증은 별도로 수행해야 합니다.

## 캡컷 연동 상태

“캡컷에서 열기”는 편집본을 캡컷이 감시하는 프로젝트 폴더에 별도 등록한 뒤 앱을 실행합니다.
현재 검증한 Mac 버전에서는 타임라인 자동 전환이 완료되지 않아 홈에서 표시된 프로젝트 이름을
직접 선택해야 합니다. API는 이 경우 `opened: false`를 반환하고 UI에도 이를 명시합니다.
앱 실행 성공을 편집본 열림 성공으로 표시하지 않습니다. 같은 편집본을 다시 등록할 때는 캡컷에서
추가 수정한 복사본을 덮어쓰지 않습니다.
